# MIFki Mini App — установка и деплой

## Что это

Telegram Mini App (веб-витрина) поверх твоей же базы `mif_core.MIFS_DATABASE` —
без новой базы данных, без раздвоения логики. Люди листают/ищут/слушают все
звуки с канала @MIFFFKI прямо внутри Telegram, могут добавлять в избранное и
отправлять звук себе в чат с ботом или делиться им в любой другой чат.

## Что добавлено / изменено

| Файл | Статус | Зачем |
|---|---|---|
| `webapp_api.py` | новый | FastAPI backend: список/поиск звуков, избранное, отправка в чат, аудио-прокси |
| `webapp/index.html` | новый | сам Mini App (HTML+CSS+JS, без сборки, один файл) |
| `db_manager.py` | обновлён | добавлены `get_favorites()` и `get_favorite_ids()` |
| `main.py` | обновлён | команда `/app`, кнопка меню бота открывает Mini App |
| `start_miniapp.sh` | новый | запуск backend + cloudflared туннель на Termux |
| `requirements-webapp.txt` | новый | `fastapi`, `uvicorn` |

`mif_loader.py`, `import_myinstants.py`, `import_tiktok.py`, `mif_core.py`,
`mif_bugs.py`, `reconcile_channel.py` — не тронуты, скопируй их как есть.

## Как это работает

- Список звуков и поиск — тот же `mif_core.find_matching_mifs`, что и в
  инлайн-режиме бота. Второй копии логики поиска нет.
- Проигрывание в приложении — `/api/audio/<id>` один раз качает файл у
  Telegram через `bot.get_file`/`download_file` и кладёт в `audio_cache/`
  рядом с ботом; дальше отдаёт его оттуда, не дёргая Telegram на каждое
  прослушивание.
- «Пост на канале» — обычная ссылка `t.me/MIFFFKI/<message_id>`, без похода
  на backend.
- Избранное и отправка в чат требуют подписанную `Telegram.WebApp.initData`
  (фронт шлёт её в заголовке `X-Telegram-Init-Data`), backend проверяет
  HMAC-подпись сам — см. `validate_init_data()` в `webapp_api.py`. Без этой
  проверки любой мог бы дёргать API от чужого имени.
- Отправка «сюда» (`/api/send`) шлёт `send_voice`/`send_audio` в чат
  `chat_id == user_id` — работает только если человек хоть раз нажимал
  боту `/start`. Это всегда так, если он попал в Mini App через кнопку
  меню бота или команду `/app`.

## Установка

```bash
pip install -r requirements-webapp.txt --break-system-packages   # на Termux
# на обычном Linux/VPS флаг --break-system-packages не нужен
```

### Переменные окружения

Добавь в `.env` (или туда же, где уже лежит `BOT_TOKEN`, `CHANNEL_ID`):

```
BOT_TOKEN=...          # уже есть у тебя
CHANNEL_ID=@MIFFFKI    # уже есть у тебя
MINIAPP_URL=           # заполнится автоматически стартовым скриптом
MINIAPP_PORT=8010      # порт, на котором крутится backend локально
```

`MINIAPP_URL` **обязательно должен быть https** — Telegram не откроет Mini
App по http.

## Запуск на Termux (твой случай)

```bash
pkg install cloudflared tmux
bash start_miniapp.sh
```

Скрипт:
1. поднимает `uvicorn webapp_api:app` в tmux-сессии `mifki-api`;
2. поднимает `cloudflared tunnel --url http://127.0.0.1:8010` в сессии
   `mifki-tunnel` (бесплатный quick tunnel, аккаунт Cloudflare не нужен);
3. вытаскивает выданный адрес `https://*.trycloudflare.com` из лога
   cloudflared и прописывает его в `.env` как `MINIAPP_URL`.

После этого перезапусти бота (команда выводится в конце скрипта) — при
старте `main.py` сам выставит кнопку меню на свежий адрес через
`bot.set_chat_menu_button`.

**Важно:** у quick tunnel адрес новый при каждом перезапуске. Для
личного/тестового использования это нормально — просто прогоняй
`start_miniapp.sh` и перезапускай бота вместе. Если захочешь постоянный
адрес — заведи бесплатный именованный туннель на домене (`cloudflared
tunnel login` → `create` → `route dns`), тогда адрес перестанет скакать и
эти два шага можно будет не повторять при каждом перезапуске.

## Проверка

1. Открой бота в Telegram → должна появиться кнопка меню с иконкой рядом с
   полем ввода. Либо отправь `/app`.
2. Список звуков должен подгрузиться сразу. Поиск, вкладки «Топ»/«Моё» —
   тоже сразу.
3. Нажми на любой звук — должен проиграться (первый раз чуть медленнее,
   Telegram отдаёт файл; дальше — из кэша).
4. Нажми ★ — должно сохраниться (перезайди в приложение, проверь вкладку
   «Моё»).
5. В плеере снизу — ➤ пришлёт звук тебе в чат с ботом, ⤴ откроет выбор
   чата для отправки через инлайн-режим бота.

## Известные ограничения / что можно улучшить дальше

- `audio_cache/` растёт с каждым новым проигранным звуком и никогда сам не
  чистится. Для сотен-тысяч звуков это не проблема (голосовые весят
  небольшие килобайты), но если база вырастет сильно — добавь простую
  очистку по возрасту/размеру.
- Один процесс `uvicorn` без воркеров — для личного/дружеского
  использования достаточно с запасом; при реальной нагрузке стоит
  запускать несколько воркеров (`uvicorn ... --workers 2`).
- initData проверяется с окном в 24 часа (`INIT_DATA_MAX_AGE_SECONDS`) —
  этого достаточно для одной открытой сессии приложения.
- Rate limiting на `/api/*` не реализован — не нужен для личного бота, но
  если дашь ссылку широкой аудитории, стоит добавить.
